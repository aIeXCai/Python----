# AI 小测编程题“重做”与单一运行入口 DEV

## 1. 实施边界

本次仅调整 AI 课学生端正式小测中的编程题工作区与试题导航：

- 将“恢复模板”改为更醒目的“重做”。
- 移除学生可见的“提交评测”、最高分和单题评测结果。
- 点击“运行代码”时，同时发起公开运行任务和后台计分任务。
- 作答页只展示公开运行任务的输出或错误；后台计分仅用于整卷交卷结算。
- 编程题导航和交卷提示改用“运行”语义。

不修改后端接口、数据库模型、Runner 协议、最终结算算法或结果页。

## 2. 技术架构设计

### 2.1 单一运行入口

`ProgrammingWorkspace` 保留一个“运行代码”按钮。按钮触发后，对同一份当前代码并行调用：

1. `runAIQuizCode(..., code, stdin)`：执行学生自定义标准输入，轮询结束后更新 `runResult`，供页面展示。
2. `submitAIQuizCode(..., code)`：使用发布时冻结的测试用例进行后台评测，轮询结束后通过现有 `onScore(itemId, score)` 通知父页面存在有效成绩。

两个请求继续使用各自现有的幂等键和执行任务机制，不新增 API。任一任务仍在执行时，“运行代码”按钮保持禁用并显示处理中状态，避免学生重复排队。

### 2.2 展示与错误边界

- 页面仅渲染 `runResult`，不再保存或渲染 `gradeResult`。
- 不展示 `bestScore`、隐藏测试结论或单题得分。
- 后台评测成功后仅向父页面传递分数，用于标记该题已经有效运行并保证最终结算可读取记录。
- 后台评测失败时保留现有错误提示能力，提醒学生再次运行，避免运行输出正常但最终没有计分记录。
- 小 P 的 `last_error` 改为读取公开运行结果中的错误，不再引用已移除的单题评测结果。

### 2.3 活跃任务恢复

组件加载时继续查询 `run` 与 `grade` 两类活跃任务：

- 活跃运行任务恢复轮询，并在完成后显示运行结果。
- 活跃后台评测任务恢复轮询，完成后更新父页面状态，但不显示评测详情。
- 题目已有 `best_score`（包括 0 分）时，继续通过 `onScore` 恢复“已运行”状态。

### 2.4 重做按钮

重做仍调用：

```js
onDraftChange(item.item_id, detail.template_code || '')
```

样式在 `aiQuiz.css` 中为 `.aiq-text-button` 增加浅紫底色、边框、圆角、内边距、字重和 hover/focus 反馈。该按钮仍是次级操作，不覆盖“运行代码”的主操作层级。

### 2.5 父页面状态文案

`QuizPage` 保留现有 `programmingScores` 状态作为“已有有效后台评测记录”的内部依据，但不向学生显示分值：

- 无记录：`尚未运行`
- 有记录（含 0 分）：`已运行`
- 交卷确认：`N 道编程题尚未运行`

最终“交卷”仍调用现有结算接口；后台计分任务若仍在执行，现有结算服务会等待任务进入终态后再生成结果。

## 6. 风险与处理

### 6.1 一次点击产生两类任务

运行与后台计分都会占用执行队列。沿用现有队列限流与错误提示；按钮在任务结束前禁用，避免连续重复创建任务。

### 6.2 运行成功但后台计分失败

运行结果照常展示，同时显示后台记录失败信息并允许学生再次运行。不会伪造“已运行”状态。

### 6.3 评测耗时长于公开运行

按钮保持处理中直到两类任务都结束，确保学生离开前后台成绩已落库。若刷新页面，现有 active execution 接口恢复轮询。

### 6.4 旧作答兼容

已有 `best_score` 的旧作答继续识别为“已运行”；不删除既有 Submission，也不改变最终取最高分规则。
