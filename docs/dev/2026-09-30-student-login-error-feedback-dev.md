# 学生登录错误精确提示 DEV

## 1. 实施边界

本次修复前端通用请求层对登录接口 401 响应的处理，使后端已有的中文登录错误能够传递到学生登录页。

涉及：

- `frontend/src/api/index.js`
- `frontend/src/api/index.test.js`
- `frontend/src/pages/auth/Login.test.jsx`

现有 `Login.jsx` 已经具备按“密码”和“不存在”关键词映射字段错误的逻辑，预计无需修改其生产代码；若测试暴露文案或可访问性问题，再做最小调整。

不修改后端登录接口、认证算法、Token 模型、数据库或迁移。

## 2. 技术设计

### 2.1 401 处理分流

为 `request(path, options)` 增加仅供 API 封装层使用的选项：

```js
redirectOnUnauthorized: true
```

该选项默认为 `true`，并在调用 `fetch` 前从 options 中解构移除，避免把非标准字段传给浏览器 Fetch API。

处理流程调整为：

1. 发起请求。
2. 尝试读取 JSON 或文本响应正文。
3. 如果状态为 401 且 `redirectOnUnauthorized` 为 `true`：
   - 清除本地 token 和 user；
   - 跳转 `/login`；
   - 保持现有 `Unauthorized` 异常行为，供受保护接口兼容使用。
4. 其他非成功响应使用后端 `error` 字段构造异常，并附加 `code`、`status` 和 `data`。

### 2.2 登录 API 特例

`login()` 调用通用请求函数时传入：

```js
redirectOnUnauthorized: false
```

因此登录接口返回 401 时：

- 不清理或跳转页面；
- 不写入 token 和 user；
- 将后端的“密码错误”“学生信息不存在”或“用户名或密码错误”作为异常信息抛出。

### 2.3 登录页映射

保留现有 `Login.jsx` 逻辑：

- 消息包含“密码” → 密码字段提示“密码错误，请重新输入”。
- 消息包含“找不到”或“不存在” → 学号字段提示身份不存在。
- 其他消息 → 表单全局错误。

本次测试以真实 API 层错误形态覆盖该映射，防止以后再次退化为 `Unauthorized`。

## 6. 风险与处理

### 6.1 401 自动退出行为回归

风险：为登录页保留错误正文时，意外关闭所有接口的自动退出。

处理：选项默认保持 `true`，仅 `login()` 显式传入 `false`，并增加受保护接口回归测试。

### 6.2 非标准选项传给 fetch

风险：自定义选项被浏览器 Fetch API 接收，造成兼容性问题。

处理：在调用 `fetch` 前解构移除 `redirectOnUnauthorized`。

### 6.3 账号枚举信息

后端现有契约已经区分“学生信息不存在”和“密码错误”。本次仅让前端正确显示既有契约，不扩大返回数据范围；不展示姓名、用户名、账号 ID 或停用状态。
