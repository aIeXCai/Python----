## 1. 接入方式

在后端新增 Django app `typing_practice`，通过 `backend/school_platform/urls.py` 挂载 API。沿用现有认证、用户模型、`users.grade_levels` 和 `users.scopes`。班级沿用现有平台的「规范年级 + 班级编号」组合，班级用于活动和海拔榜隔离。

现有学生登录成功后跳转到 `/course-select`。在该欢迎页的 `CourseSelect.jsx` 加一张与课程入口并列的「打字训练」卡片，点击进入 `/student/typing`。教师从 `TeacherDashboard.jsx` 原地打开统一参数弹窗，设置文章模式和中文拼音。兼容地址 `/teacher/typing` 跳转到首页并打开弹窗。页面接入 `App.jsx`，请求使用现有 API 客户端。打字和结算均可独立于代码 Runner 运行。

题库支持导入三至八年级。首轮在已有账号体系中开放七、八年级。开启三至六年级前，在单独迁移中补齐后端年级枚举、注册年级编码、前端表单、教师管理年级、学生身份和相关数据库约束。同步回归原有课程的注册、登录、学号唯一性、可见范围和教师权限，然后启用对应年级入口。

## 2. 数据与权限

| 实体 | 关键字段与约束 |
| --- | --- |
| 文章版本 `TypingArticleRevision` | 稳定文章 ID、版本、来源批次和原始 ID、规范化正文及摘要哈希、年级、语言、难度、分册与单元、来源与审阅状态、可选的按字位拼音。唯一键为文章 ID + 版本。批准后改正文或拼音须建新版本。 |
| 班级设置 `TypingClassSettings` | 规范年级和班级编号唯一，指向当前生效的活动版本。 |
| 场次 `TypingActivity` | 创建教师可空，留空表示系统默认。保存规范年级、班级编号、版本启用及替换时间、试用标志。每种语言保存山峰、路线版本、文章模式、允许的文章版本池、难度及每篇目标速度快照。中文另外保存拼音开关。 |
| 练习 `TypingAttempt` | 学生、场次、语言、年级快照、开始与截止时间、状态、固定文章版本、最后确认批次、文本进度及首次输入计数。结算保存分数、有效字速、正确率、海拔、登顶时间和所用规则版本。 |
| 积分提交 `TypingPointSubmission` | 唯一练习 ID、学生、场次、语言、分数、积分、规则版本、结算时间、环境标志和消费状态。分数与积分采用相同小数精度。 |

练习分别为 `active`、`settled` 或 `void`。启动在事务内为学生认领唯一活动练习，用数据库唯一键保护并发双击和多标签页，结算或作废时释放。场次＋语言、学生＋语言＋试用标志和状态＋截止时间分别建索引，支持榜单、个人最佳和过期结算查询。

教师的管理资格从登录身份解析。统一参数作用于所有已开放班级，固定文章依年级和语言分别配置。学生可见活动和榜单须同时满足账号年级与班级，读写练习还须校验练习归属。学生首次访问时按班创建默认活动，中英文优先用基础档随机选文，拼音关闭。班级设置行事务内锁定，确保全班共用一份当前活动。教师保存设置时创建新版本，替换旧版本。已有练习引用原山峰、文章和计分规则，按原截止时间继续。

## 3. 题库导入与年级过滤

1. 计划提供 `manage.py import_typing_bank <jsonl> --dry-run`，支持 WorkBuddy 的全量文件或单年级、单语言文件。同一批次只需选一种导入。干运行报告有效行、错误行及待审条目，正式执行默认导入草稿。
2. 从 `grade` 数值映射规范年级，并验证 `grade_label` 一致。检查语言、正文段落、重复、英文键盘字符、来源及教材字段。篇幅偏短记入报告，中文随机优先使用不少于 180 个汉字的非诗歌文章。导入时保留源文件 ID，平台分配稳定 ID。再次导入相同内容可跳过，源 ID 指向不同正文时进入待核对流程，审核确认后才创建新版本。
3. 优先审阅七、八年级候选文章。处理公版误标和来源不具体的条目，按学校手头教材核对存疑的分册。中文生成按规范化正文索引的拼音，多音字可逐字修订。开启拼音的场次只能使用具备已审阅注音的版本。课程正文与版权材料在确认后进入可发布题池。
4. 后端统一查询条件为「活动年级 × 语言 × 难度 × 可发布版本」。教师文章列表、发布、学生选文、开始均按该规则或发布时冻结的合格题池校验。跨年级直接提交文章 ID 时返回明确错误。题池为空时给出对应年级和语言的提示。
5. 固定模式使用该年级该语言的指定篇目，随机模式从同档题池抽取，自由模式由学生从同档池中自选。每场一篇，打完即结算，最长五分钟。刷新恢复原文章和已确认输入。

## 4. 输入、计时与结算

### 登录后欢迎页

- 卡片显示「中文最佳成绩」「英文最佳成绩」两行，成绩为百分制分数。尚无成绩时显示「暂无成绩」，加载失败时显示「成绩暂不可用」，仍可进入打字训练。试用库读试用成绩并标明「试用」，正式环境读正式成绩。
- 欢迎页加载及结算后返回时请求 `GET /api/typing/me/bests/`。接口从当前登录账号读取有效结算记录，无成绩的语言返回 `null`。切换账号时清除上一账号的成绩状态，取消或忽略其尚未完成的请求。以服务器已结算数据为准，欢迎页保留两项历史最佳，题库不足时在训练页提示联系教师。
- 个人最佳详情仍可展示有效字速、正确率、山峰和日期。欢迎页卡片只显示两项分数，方便学生一登录就能看到。

### 页面与输入

复用 Demo 的左榜、山景、双行字位和居中结果弹窗。原文与输入使用同一组字位及折行边界，随当前字位滚动。输入通过真实可聚焦文本控件接收，IME 组合期间展示预编辑状态，`compositionend` 后仅判定一次。支持退格改错，拦截粘贴和拖入，导入时保留段落结构，英文段间统一为一个空格，中文段落边界只作排版。屏幕自动折行无输入要求。字位可用键盘或点击查拼音，关闭提示或山峰简介时恢复输入焦点和光标，倒计时继续。批量状态同步与本地输入渲染分开，榜单刷新保留滚动位置。

十四座山各有独立的 WebP、路线节点坐标、简介和参考海拔。班级首次开放及北京时间跨日时抽取两座不同的山，避开上一组，中文和英文各保存一座。设置变更沿用当天山峰。插画与线条共用同一坐标系和裁切方式，路线渲染为山景上的细红线，仅标 BC 和营地名称。按当前海拔在相邻节点之间沿路线插值移动标记，亮起到达的营地。动画使用本地资源，进入时加载所选山峰，切换语言时按需加载另一座。

### 计分与计时

- 用服务端开始时刻加 300 秒计算截止时间。响应带 `server_now`，前端据此校对倒计时。服务端接受截止时刻及之前确认的有效批次。掉线可在截止前补发，截止后以最后已确认的输入结算。
- 中文有效单位为正确汉字，标点参与比对和正确率。英文按题面逐字符比对，含大小写、空格和标点，每 5 个正确字符为 1 个等效词。每个文章实例的每个字位记录首次提交是否正确，退格纠错替换该字位的结果，首次判定保留，有效工作量只计一次。正确率为当前正确字位数除以当前已输入字位数，退格修正后重新计算。结算读取最后确认的文本，无输入时记为零。练习完成前可点击字位或用方向键定位并替换。
- 每个文章实例累计 `正确有效单位 × 60 ÷ 该版本的目标单位/分钟`，将各篇的目标秒数相加。进度为 `min(累计目标秒 ÷ 300, 1)`，整数展示海拔为 `BC + 进度 × (峰顶 − BC)` 四舍五入。保留足够精度计算临界达标和榜单排序，结算成绩统一四舍五入至一位小数。登顶条件以原始进度达到 100% 为准。未达标的分数最高显示并保存为 99.9，榜单整数海拔最高显示为峰顶以下 1 米。
- 目标速度以年级 × 语言 × 难度配置，可加单篇覆盖值。每次发布冻结速度线与规则版本。示例使用中文 40 字/分钟，五分钟打对 160 字为 80.0 分和 80.0 积分。这个数值用于验算，试用速度线由教师配置，正式速度线用同年级交叉试打校准。拼音开关纳入试打条件。
- 服务端保存首次达标的确认时间。登顶可继续输入，海拔封顶，最终进度达标时展示首次达标用时。结算弹窗读取成绩数据，展示登顶状态、海拔、成绩、积分、有效字速、正确率、登顶用时和是否刷新个人最佳。结算字速按有效练习时间计算。相同语言的试用最佳与正式最佳独立查询，比较分数，同分保留较早取得的成绩。

## 5. API 与两秒同步

下列接口为第一版约定，均由后端验证当前账号的权限与对象范围。

| 入口 | 请求与返回 |
| --- | --- |
| `GET /api/typing/teacher/settings/`、`POST /api/typing/teacher/settings/` | 读取或保存全体班级统一使用的文章模式与拼音开关。保存后对新开练习生效。 |
| `GET /api/typing/teacher/settings/articles/?pinyin=false` | 返回固定模式的分年级、分语言可选篇目。 |
| `GET /api/typing/activities/` | 返回学生所在班级当前可用的默认或教师配置，以及语言和可选文章摘要。 |
| `POST /api/typing/attempts/` | 提交场次、语言及自由模式的所选文章版本。返回练习 ID、已分配正文、山峰、时间和已确认的输入状态。重复开始同场同语言返回已有进行中练习，其他活动已有进行中练习时提示恢复。 |
| `GET /api/typing/attempts/{id}/` | 恢复同一练习或读取已结算结果，供刷新和重连使用。 |
| `POST /api/typing/attempts/{id}/sync/` | 提交未确认的输入增量。返回确认批次、个人进度、本场同语言榜单、服务端时间及练习状态。 |
| `GET /api/typing/activities/{id}/leaderboard/?language=zh` | 供预览、已完成页面读取同语言榜单。 |
| `POST /api/typing/attempts/{id}/pause/`、`POST /api/typing/attempts/{id}/resume/` | 暂停时同步最后输入并冻结剩余时间。恢复时将截止时间顺延暂停时长，浏览器可从原字位继续。 |
| `GET /api/typing/me/bests/` | 按当前登录账号返回 `zh` 和 `en` 的已结算最高分。对应语言无结算记录时返回 `null`。试用成绩与正式成绩按环境分别统计。 |
| `GET /api/typing/me/bests/?period=today` | 按北京时间当天的结算时间筛选最高分。训练页在结算后及午夜刷新。 |

学生进入练习后每 2 秒发出一轮同步。输入增量只发尚未确认的批次，带递增批次号和有序输入变更，每项含文章实例序号、字位以及新增或删除的字符。用变更顺序重放首次输入，保留同一批次内已经纠正的错误。后端按序验证篇目、字位与截止时间、比对正文、派生分数并持久化确认位点。重试沿用原批次号和内容，重复收到即回传确认状态，跳号时返回所需的下一批次号。服务端限制单批大小，批次边界与字位均经验证。客户端避免轮询请求堆积，逾时显示同步提示并按确认位点重试。临近截止时尽快发送剩余输入，结果弹窗以结算响应为准。预览和完成状态如需展示榜单，使用只读入口按同一节奏刷新。

榜单按场次和语言查询，取每名学生已确认的实时进度与本场已结算最佳的较高者，标明来源。按未取整进度排序，同进度并列，达到 100% 全部并列。左榜只返回班内展示名或学号、进度、海拔和状态。45 名学生练习时，合并接口平均约 22.5 请求/秒。开发验收需覆盖同一秒开始、同步和结算的峰值。

最后一批确认和到期结算通过同一练习并发控制串行处理。过期同步或恢复请求可触发结算，提供按截止时间索引查询的结算命令，由试用环境定时执行，兜底处理关页或断线的练习。结算在同一数据库事务写入成绩和唯一积分记录，并释放进行中占位。积分接入时可按练习 ID 读取待处理记录，消费方用同一 ID 幂等记账。每次有效重练可单独获得积分，积分等于本次成绩。试用积分记录只在试用库内验证。
