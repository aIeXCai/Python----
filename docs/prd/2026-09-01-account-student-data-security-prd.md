# 阶段 3：账号与学生数据安全 PRD

文档日期：2026-09-01
文档状态：已确认（2026-09-01）
对应路线图：阶段 3「账号与学生数据安全」

## 1. 背景与问题

当前系统为了方便教师帮助忘记密码的学生，在 `CustomUser.plain_password` 中直接保存学生密码，并通过 `GET /api/auth/<user_id>/` 将该值返回给教师端。教师页面默认遮罩密码，点击眼睛图标后获取并显示明文。

这一设计满足了课堂上快速协助学生的需要，但存在明显风险：

- 数据库、SQLite/MySQL 备份和阶段 2 导出文件中都存在可直接读取的学生密码。
- 学生注册和教师重置密码时，需要同时维护 Django 密码哈希与明文副本。
- 学生详情与密码查看共用一个接口，普通详情请求也会取得密码。
- 查看密码没有独立审计记录、限流或自动隐藏规则。
- 教师重置学生密码后，学生已经持有的 Token 不会主动失效。
- 当前 Token 没有明确的最长有效时间，成功登录会持续复用同一 Token。
- 多个管理接口分别手工判断 `request.user.role`，需要系统性验证匿名、学生和教师权限边界。

本阶段保留已经确认的教学业务要求：**教师后台仍可快速查看学生当前密码**。安全改造的重点不是取消这项能力，而是将“数据库明文存储、普通详情直接返回”改为“加密存储、单独授权解密、短时展示并记录审计”。

## 2. 目标

1. 保留教师后台查看单个学生当前密码的能力，不影响课堂上快速处理忘记密码问题。
2. 删除当前数据库的 `plain_password` 明文字段，改为只有应用在持有独立密钥时才能解密的密文。
3. 将学生普通详情和密码揭示拆为不同接口，普通接口、列表、日志和导出均不得包含明文密码。
4. 为每次密码查看、重置及失败尝试建立不含密码内容的安全审计记录。
5. 统一注册、教师重置等密码写入路径，保证 Django 登录哈希和可恢复密文始终同步。
6. 在密码修改或重置后撤销该学生的旧 Token，并完善 Token 过期、注销和重新登录行为。
7. 增加匿名、学生、教师的接口和前端路由权限测试，防止仅修改前端请求即可越权。
8. 安全迁移历史明文，并处理阶段 2 遗留的含明文密码迁移产物。

## 3. 非目标

- 不取消教师查看学生当前密码的业务能力。
- 不允许学生、匿名用户或非教师账号查看任何可恢复密码。
- 不允许批量查看、批量导出或通过学生列表接口取得密码。
- 不在本阶段引入学校统一身份认证、短信、邮箱或家长找回密码流程。
- 不在本阶段创建多种教师权限等级或重新设计教师管理年级业务；现有 `role=teacher` 仍是密码管理授权条件。
- 不将教师自己的密码改为可恢复密码；教师密码仍只保存 Django 不可逆哈希。
- 不修改 AI 题库、信息课小测、Runner 或阿里云部署架构。
- 不把浏览器本地存储中的 Token 全面替换为 HttpOnly Cookie；该认证架构升级可在后续独立阶段评估。

## 4. 用户故事

### 4.1 教师

- 作为已登录教师，我在学生管理页面仍能点击眼睛图标，快速查看某一个学生的当前密码。
- 作为教师，我看到的密码默认被遮罩，主动确认查看后短时显示，之后自动隐藏。
- 作为教师，我可以为学生设置新密码或生成临时密码；修改完成后学生旧登录立即失效。
- 作为教师，当历史密码无法安全迁移时，我能看到“密码不可查看，请重置”，而不是错误或过期密码。

### 4.2 学生

- 作为学生，我仍可使用原有年级、班级、学号和密码登录。
- 作为学生，我无法通过页面、接口参数修改或直接请求查看自己或其他学生的可恢复密码。
- 作为学生，教师重置我的密码后，旧密码和旧 Token 均不能继续使用。

### 4.3 运维与安全管理

- 作为运维人员，我在数据库中只能看到密文，不能直接读取学生密码。
- 作为运维人员，我可以轮换或配置加密密钥，且密钥不会进入仓库、数据库、日志或迁移产物。
- 作为安全管理人员，我可以确认哪位教师在什么时间查看或重置了哪位学生的密码，但审计记录本身不包含密码。
- 作为运维人员，我可以安全迁移现有数据，并识别哈希与历史明文不一致的异常账号。

## 5. 功能需求

### 5.1 学生可恢复密码的加密存储

1. 从当前用户模型删除 `plain_password` 明文字段。
2. 新增学生可恢复密码密文字段；数据库列、数据库备份和 Django 普通序列化结果中只能出现密文。
3. 使用带完整性校验的认证加密方案；篡改、密钥错误或密文损坏时必须拒绝解密，不得返回乱码或猜测值。
4. 加密密钥通过环境变量或生产密钥服务提供，不写入源代码、数据库、日志、测试快照和示例文件。
5. development、test、production 均有明确密钥配置；production 缺少或使用明显占位密钥时拒绝启动。
6. 密文需要携带或关联密钥版本，为后续轮换保留能力。
7. 只有学生账号保存可恢复密码；教师和其他角色不得保存可恢复副本。
8. Django 原有 `password` 哈希字段继续作为登录验证的唯一依据；解密出的密码不得替代 `check_password` 登录流程。

### 5.2 密码写入一致性

以下场景必须通过统一的密码服务同时更新 Django 哈希和加密密文：

1. 学生注册。
2. 教师为学生设置新密码。
3. 教师生成并应用临时密码。
4. 后续若开放学生主动修改密码，也必须复用同一服务。

写入规则：

- 两项更新在同一个数据库事务内完成，任一失败则全部回滚。
- 更新后立即在进程内验证新密码能够通过 `check_password`，且密文可正确解密。
- 禁止直接对学生调用 `set_password` 后遗漏密文更新；代码和测试需要覆盖所有现有写入入口。
- 密码不得出现在成功响应、异常信息、日志或审计详情中；只有专用揭示接口可以返回明文。

### 5.3 教师查看学生密码

新增独立的单学生密码揭示接口，替代普通学生详情返回 `plain_password`：

1. 仅接受已通过 Token 认证且数据库角色为 `teacher` 的请求。
2. 每次只允许查看一个明确的学生 ID；不存在批量接口。
3. 请求前端展示确认提示：“查看操作将被记录，请仅用于帮助学生登录”。为保证课堂效率，本阶段不要求教师每次重新输入自己的密码。
4. 成功响应只包含本次需要显示的密码和最小必要元数据，不包含密文或密钥信息。
5. 学生无可恢复密码、历史迁移失败或密文损坏时返回明确的“不可查看，请重置”状态，不返回空字符串冒充密码。
6. 对单教师的密码揭示请求执行可配置限流，默认每分钟最多 30 次；超过限制返回 HTTP 429 并记录失败审计。
7. 普通学生详情、学生列表、搜索、排序、批量导出和统计接口不得触发解密，也不得包含密码字段。
8. 任何解密或权限失败均使用安全错误信息，不暴露密钥配置、密文、算法、堆栈或学生密码。

### 5.4 教师端展示交互

1. 学生管理列表继续显示固定密码遮罩和眼睛图标。
2. 教师点击后先出现轻量确认提示，确认才请求专用揭示接口。
3. 明文只保存在当前页面组件内存中，不写入 `localStorage`、`sessionStorage`、URL、缓存或浏览器日志。
4. 明文显示 30 秒后自动恢复遮罩；教师也可以立即点击隐藏。
5. 页面离开、弹窗关闭、用户退出或组件卸载时立即清除已显示的密码状态。
6. 请求失败、权限不足、限流或密码不可恢复时显示对应中文提示，不使用 `********` 掩盖真实失败。
7. 页面不得一次预取多个学生密码；刷新列表也不得重新请求已查看密码。

### 5.5 密码重置与临时密码

1. 保留教师手工输入新密码的能力。
2. 增加生成安全随机临时密码的能力，由服务端生成并立即设置；响应仅向发起操作的教师显示一次。
3. 临时密码或手工新密码更新成功后，撤销该学生现有全部 Token。
4. 旧密码不能再登录；旧 Token 不能再访问任何受保护接口。
5. 教师重置完成后可通过正常查看入口再次查看当前密码。
6. 密码输入执行统一长度和格式验证；具体阈值在 DEV 中结合现有账号数据确定，不得导致历史学生在未修改密码时突然无法登录。
7. 本阶段不强制学生首次登录后修改临时密码，以免增加课堂操作阻力；界面应明确标记该密码由教师刚刚重置。

### 5.6 Token 生命周期

1. 保留 DRF Token Authentication，避免本阶段扩大为认证框架重写。
2. Token 最长有效时间通过环境变量配置，默认 12 小时；过期 Token 返回 HTTP 401，并在安全条件下删除或失效。
3. 登录时不得继续返回已经过期的 Token；应签发新的 Token。
4. 正常注销删除当前 Token，后续使用该 Token 返回 HTTP 401。
5. 教师修改或重置学生密码后删除该学生全部 Token。
6. 用户被禁用或删除后，其 Token 不得继续访问系统。
7. Token 原值不得写入应用日志、审计日志、错误响应和前端调试输出。
8. Token 有效时间配置在测试中可缩短，以验证边界，不依赖真实等待 12 小时。

### 5.7 安全审计

审计事件至少包括：

- 教师成功查看学生密码。
- 查看被拒绝、目标不存在、密文不可恢复或触发限流。
- 教师手工重置学生密码。
- 教师生成临时密码。

每条记录只保存：事件类型、教师用户 ID、目标学生 ID（存在时）、成功/失败、时间、请求来源的最小必要信息和不含敏感值的原因代码。

审计要求：

- 不保存明文密码、密文、Token、Authorization 请求头或请求正文。
- 审计记录不能通过学生 API 读取。
- 本阶段不制作复杂审计管理页面；先确保数据可靠记录，可通过 Django 管理或管理命令核查。
- 审计写入失败不能把密码内容带入异常日志；是否阻断揭示操作由 DEV 根据事务和可用性设计确定，默认采用失败关闭策略。

### 5.8 历史数据迁移

迁移按“新增密文字段 → 校验并回填 → 核对报告 → 删除明文字段”执行：

1. 只处理 `role=student` 且 `plain_password` 非空的记录。
2. 回填前必须使用 Django `check_password(plain_password, password_hash)` 验证两者一致。
3. 验证一致才允许把历史明文加密写入密文字段。
4. 明文为空、哈希不一致或加密失败的学生不得生成虚假密文，标记为不可恢复并要求教师重置。
5. 迁移报告只输出总数、成功数、不可恢复数和失败原因计数，不输出用户名、明文、哈希或密文。
6. 回填报告通过并完成抽查后，删除当前模型和数据库中的 `plain_password` 列。
7. 同一迁移流程必须同时兼容 SQLite 开发库和 MySQL 8.0。
8. 原有 Django migration 历史文件可以保留字段定义以支持从零建库，但当前最终 schema 不得存在明文字段。

### 5.9 阶段 2 敏感产物处理

阶段 2 的 SQLite 备份和 `platform-data.json` 含历史明文密码：

1. 阶段 3 数据迁移验证完成前，继续保持 Git 忽略、目录 `0700`、文件 `0600`，不得传播或提交。
2. 阶段 3 完成后，明确列出需要安全删除的旧产物，并在执行删除前再次核对路径。
3. 如仍需保留迁移演练能力，应基于已完成阶段 3 schema 的数据库重新生成不含明文字段的新迁移产物。
4. 删除旧产物属于不可逆数据操作，实施时需要单独向用户说明具体目标；未经确认不擅自删除。

### 5.10 角色和接口权限

1. 密码揭示、重置、临时密码和学生删除接口统一使用后端教师权限类，不只依赖前端路由。
2. 匿名请求返回 HTTP 401；已登录学生或非教师角色返回 HTTP 403。
3. 目标必须是 `role=student`；不得通过学生 ID 参数查看或修改教师密码。
4. 前端教师路由仍进行体验层保护，但后端权限是最终安全边界。
5. 本阶段保持现有教师可以管理全部学生的行为；按 `managed_grade` 限制教师范围需要另行确认后再设计，避免无意改变现有教学流程。

## 6. UI / UX 规格

### 6.1 学生管理列表

- 密码列默认显示 `••••••••`。
- 右侧保留眼睛图标，点击后弹出简短确认提示。
- 显示成功后眼睛图标切换为隐藏状态，并展示 30 秒倒计时或“30 秒后自动隐藏”提示。
- 不改变现有搜索、筛选、排序和编辑学生的主要布局。

### 6.2 密码不可恢复

- 该学生显示“密码不可查看，请重置”。
- 教师可直接进入重置操作，不能看到历史错误值。
- 重置成功后仅当前教师看到新密码，并提示旧登录已失效。

### 6.3 错误提示

- 401：登录状态已失效，请重新登录。
- 403：当前账号没有教师管理权限。
- 404：学生不存在。
- 429：查看过于频繁，请稍后再试。
- 密文异常：密码暂时无法查看，请为学生重置密码。

错误提示不得包含技术堆栈、密文或密钥信息。

## 7. 资源与约束

- 后端：Django 5、Django REST Framework、DRF Token、SQLite/MySQL 8.0 双数据库。
- 前端：React/Vite，当前 Token 保存在浏览器 `localStorage`。
- 现有数据量很小，但迁移必须按全量真实数据设计，不能依赖手工逐账号修改。
- 需要增加成熟、维护中的认证加密依赖；禁止自行发明加密算法。
- 加密密钥必须独立于 Django `SECRET_KEY`，支持不同环境使用不同值。
- 阿里云正式密钥的保存位置在部署阶段确定；本阶段先完成环境变量边界和本地验证。
- 实施期间不能打印、展示或提交真实学生密码、Token 或加密密钥。
- 当前阶段 2 本地 MySQL 已停止，阶段 3 DEV 确认后可按既有脚本临时启动进行 MySQL 验证。

## 8. 非功能需求

### 8.1 安全

- 密码密文使用认证加密，数据库管理员仅凭数据库内容不能直接还原密码。
- 加密密钥、明文密码和 Token 不进入 Git、日志、审计记录、错误响应和迁移报告。
- 普通学生读取接口永远不解密密码。
- 密码揭示接口具备身份验证、角色校验、单目标限制、限流和审计。
- production 密钥配置不安全时失败关闭，不静默退回明文或固定默认密钥。

### 8.2 一致性

- 学生密码哈希和密文更新必须原子完成。
- 所有可恢复密码在内部抽查时必须通过 `check_password`，但报告只输出通过数量。
- 密码重置与 Token 撤销必须在一致的操作边界中完成，不能出现新密码已生效但旧 Token 仍有效。

### 8.3 性能与可用性

- 单次密码解密和审计写入不得明显阻塞学生管理页面。
- 学生列表不得批量解密，因此学生数量增长不会线性增加解密操作。
- 密钥或密文异常时只影响密码查看/重置相关功能，不向用户暴露内部错误。

### 8.4 可测试性

- 测试使用独立固定测试密钥，不使用开发或生产密钥。
- 时间、Token 过期和限流逻辑可注入或覆盖配置，不依赖长时间等待。
- SQLite 与 MySQL 均运行账号安全相关测试。

## 9. 验收标准与验证方法

### 9.1 数据存储与迁移

- 当前最终 schema 不存在 `plain_password` 字段。
- 数据库中不出现本次测试使用的已知明文密码。
- 历史哈希匹配的学生密码可在教师专用接口中正确查看，并仍可正常登录。
- 哈希不匹配、空值或损坏密文的账号显示不可恢复，必须重置。
- SQLite 和 MySQL 8.0 均成功执行新增、回填和删除字段迁移。
- 阶段 2 迁移/校验工具不再依赖 `plain_password`，新产物不含明文字段。

### 9.2 密码查看

- 教师可以查看单个学生当前密码，页面 30 秒后自动隐藏。
- 普通学生详情和列表响应不含明文、密文或类似 `plain_password` 的字段。
- 匿名访问揭示接口返回 401，学生访问返回 403，教师查看非学生目标返回安全错误。
- 连续超过限流阈值返回 429。
- 每次成功或失败查看都生成不含敏感值的审计记录。

### 9.3 密码重置与 Token

- 教师手工重置和随机临时密码两条流程均可用。
- 重置后新密码可以登录，旧密码不能登录。
- 重置前的学生 Token 立即返回 401。
- 正常注销后旧 Token 返回 401。
- 超过配置有效期的 Token 返回 401，重新登录获得新 Token。

### 9.4 前端与权限

- 教师学生管理页的默认遮罩、确认、查看、自动隐藏、立即隐藏和失败提示测试通过。
- 页面卸载或教师退出后，组件状态中不保留已经显示的密码。
- 学生不能通过直接访问教师路由或直接调用管理 API 绕过权限。
- 修改请求中的学生 ID、角色字段或目标类型不能访问教师密码或其他受限数据。

### 9.5 回归

- 后端新增安全测试全部通过，后端全量回归不得增加失败。
- 前端账号管理、认证上下文、教师登录、学生登录和学生管理测试通过。
- SQLite 与 MySQL 的账号安全测试结果一致。
- 静态扫描确认源代码、可跟踪文件、日志和报告中没有真实密码、Token 或加密密钥。

## 11. 风险与应对

- 风险：任何可恢复密码设计都比“只保存哈希、只能重置”风险更高。应对：只保存认证加密密文，独立管理密钥，单学生按需解密，限流、短时展示并完整审计。
- 风险：应用服务器和密钥同时失陷后密码可被还原。应对：生产密钥与数据库分离保存、限制运行身份和配置权限，并为未来密钥轮换保留版本字段。
- 风险：历史 `plain_password` 与实际哈希不一致。应对：迁移前逐条 `check_password`，不一致账号不迁移旧值，只允许教师重置。
- 风险：密钥丢失导致密码无法查看。应对：登录哈希不受影响，学生仍可登录；教师可重置密码生成新密文。生产密钥备份策略在部署 DEV 中明确。
- 风险：前端已显示的密码被旁观者看到。应对：默认遮罩、主动确认、30 秒自动隐藏、页面离开立即清除；同时通过教师培训强调只在帮助对应学生时查看。
- 风险：查看接口被教师账号批量抓取。应对：不提供批量接口、设置频率限制、记录目标和教师审计；异常查看可从审计中追踪。
- 风险：密码重置后旧 Token 仍可访问。应对：重置流程中同步删除学生 Token，并用旧 Token 实际请求验证 401。
- 风险：阶段 2 旧备份继续保存明文。应对：阶段 3 验证后列出精确目标，经用户确认后安全删除，并重新生成不含明文字段的迁移产物。

## 12. 回滚原则

1. 删除 `plain_password` 前必须有受控的迁移前备份和回填统计，但备份按最高敏感级别保管。
2. 加密回填或核对失败时停止在“新旧字段并存”阶段，不删除旧字段，不对外启用新揭示接口。
3. 密文字段验证通过后才执行删除明文字段迁移；删除后不通过日志、导出或历史产物恢复日常明文读取。
4. 前端新交互异常时可以回退为“只允许重置、暂时不可查看”，不能回退到普通详情直接返回明文。
5. Token 过期认证异常时可以暂时恢复原认证类，但注销和密码重置撤销 Token 的安全行为不得回退。

## 13. 确认项

确认本 PRD 即表示同意以下产品决策：

1. 教师仍可查看学生当前密码，但数据库不再直接保存明文。
2. 教师登录后点击确认即可查看，不要求每次重输教师密码；显示 30 秒后自动隐藏。
3. 密码查看拆为单学生专用接口，并执行教师角色校验、默认每分钟 30 次限流和安全审计。
4. 教师既可以手工重置密码，也可以生成一次性展示的随机临时密码。
5. 密码重置会让学生全部旧 Token 立即失效；Token 默认最长有效 12 小时并允许环境变量调整。
6. 当前阶段保持所有教师可以管理全部学生，不启用 `managed_grade` 范围限制。
7. 历史明文仅在与密码哈希一致时加密迁移；异常账号必须重置。
8. 阶段 2 旧敏感产物在阶段 3 验证完成后另行列出并征得确认，再执行安全删除。

PRD 确认后才编写阶段 3 DEV 技术设计；DEV 再次确认后才修改数据库、后端和前端代码。
