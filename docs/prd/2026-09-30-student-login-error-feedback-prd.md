# 学生登录错误精确提示 PRD

## 1. 背景与问题

学生登录接口已经能够区分并返回“密码错误”和“学生信息不存在”。但前端通用请求函数遇到任何 HTTP 401 时，会在读取后端响应正文之前直接抛出 `Unauthorized`，导致学生登录页无法获得后端提供的中文错误信息。

当前结果是：学生密码输入错误时，页面显示缺乏指导意义的英文 `Unauthorized`，学生无法判断是密码错误、账号信息选择错误，还是系统异常。

## 2. 目标

- 学生密码错误时，在密码输入框附近明确提示“密码错误，请重新输入”。
- 年级、班级、学号组合不存在时，在学号附近提示学生检查身份信息或先注册。
- 保持已登录用户访问受保护接口遇到 401 时的现有安全行为：清除失效登录状态并跳回登录页。
- 不暴露密码、密码哈希、账号内部标识或服务器调试信息。

## 3. 用户故事

作为学生，当我输错密码时，希望页面直接告诉我密码不正确，以便立即重新输入，而不是看到无法理解的 `Unauthorized`。

作为学生，当我选择的年级、班级和学号不存在时，希望页面提示我检查身份信息或先注册，而不是误以为只是密码错误。

## 4. 功能规格

### 4.1 登录请求错误传递

1. 通用请求函数增加“401 是否自动跳转登录页”的内部选项，默认保持开启。
2. 登录 API 调用时关闭该自动跳转行为，使请求函数能够读取登录接口返回的 JSON 错误正文。
3. 登录失败时按正常非成功响应构造错误对象，保留：
   - 后端 `error` 中文信息；
   - HTTP 状态码；
   - 后端业务错误码（如后续增加）；
   - 响应数据。
4. 已登录用户请求其他受保护接口得到 401 时，继续清除本地 token 和用户信息，并跳转 `/login`。

### 4.2 学生登录页提示

1. 后端返回“密码错误”时，在密码字段下显示：`密码错误，请重新输入`。
2. 后端返回“学生信息不存在”时，在学号字段下显示：`找不到该年级班级学号的学生，请检查或先注册`。
3. 网络错误、服务器异常或无法识别的错误，在表单区域显示中文全局提示，不显示裸英文 `Unauthorized`。
4. 登录失败后保留学生已选择的年级、班级、学号和已填写姓名，方便只修改错误项。
5. 登录失败后停止“登录中...”状态，允许再次提交。

## 5. UI/UX 规格

- 错误继续沿用现有 `.field-error` 和 `.global-error` 样式，不新增弹窗。
- 密码错误紧邻密码框显示，身份不存在紧邻学号下拉框显示。
- 不自动清空密码；学生可自行修改，也可使用现有显示/隐藏密码功能检查输入。
- 所有新增或修复后的用户可见错误均使用中文。

## 6. 功能边界

本次不包含：

- 修改密码、找回密码或重置密码流程。
- 修改学生账号注册规则。
- 校验登录页“姓名”与账号档案姓名是否一致。
- 修改教师登录接口返回规则；教师登录会同步受益于登录请求能够显示后端“用户名或密码错误”。
- 修改后端认证算法、Token 生命周期、数据库模型或迁移。
- 展示账号是否被停用等更细粒度的内部状态。

## 7. 安全与非功能要求

- 不在控制台、页面或错误对象中输出学生明文密码。
- 普通受保护 API 的 401 自动登出行为不得回归。
- 登录错误响应不得写入 token 或 user 本地存储。
- 修复不得依赖英文 HTTP 状态文本。
- 保持现有浏览器和移动端表单布局。

## 8. 验收标准

1. 使用存在的学生身份和错误密码登录，页面密码字段下显示“密码错误，请重新输入”，不出现 `Unauthorized`。
2. 使用不存在的年级、班级、学号组合登录，页面学号字段下显示身份不存在提示。
3. 登录失败后不跳离当前学生登录页，表单内容得到保留，并可再次提交。
4. 使用正确密码仍正常进入课程选择页并保存 token 和用户信息。
5. 已登录状态下调用受保护接口收到 401，仍清理本地登录信息并跳转登录页。
6. API 层、登录页和现有认证相关测试全部通过。

## 9. 成功指标

- 新增的登录 API 401 错误正文测试通过。
- 学生登录页的密码错误与身份不存在测试通过。
- 前端完整测试和生产构建通过。
- 无后端代码、数据库迁移和接口契约变更。
