# 七年级 Python 第二单元第一章《在编辑区调试第一段代码》课程内容 PRD

## 1. 背景与问题

七年级学生已经完成第一单元，认识了程序、指令、算法和“输入—处理—输出”，也知道指令需要明确、有序，并运行、修改过简单的 `print()` 程序。因此，第二单元不能再以“计算机不会猜”或“哪条指令更明确”为主要新授内容。

本章将第一单元的概念提升为真实的代码调试方法：学生直接在学习平台编辑区运行一段只含 `print()` 的错误代码，通过控制台反馈定位问题，每次修改一处并重新运行，直到实际输出与目标输出一致。课程重点从“知道指令要明确有序”转向“能根据证据修改程序”，并为后续比较方案、流程图和独立编程建立调试习惯。

## 2. 课程定位

- 年级：七年级。
- 单元：第二单元“像程序员一样检查和改进方案”。
- 章节：第一章“在编辑区调试第一段代码”（全课程第 3 课）。
- 建议课时：1 课时，40～45 分钟。
- 前置知识：程序、指令、输入、处理、输出；运行过简单的 `print()` 程序。
- 后续衔接：第二章“同一个问题可以有不同方案”。
- 本章代码边界：不讲变量、条件、循环等语法，不要求学生独立编写完整 Python 程序。

## 3. 核心问题与学习目标

### 3.1 核心问题

> 当一组步骤没有得到预期结果时，怎样找到问题并把它改好？

### 3.2 学习目标

完成本章后，学生能够：

1. 区分“预期结果”和“实际结果”，并用简短文字记录两者的差异。
2. 区分“代码不能运行”和“代码能运行但结果不符合要求”两种情况。
3. 从控制台反馈中找到需要优先检查的代码行，并对照英文括号、英文引号和目标输出定位问题。
4. 每次只修改一处问题，点击运行重新验证，直到实际输出与目标输出一致。
5. 用“第几次运行—发现什么—修改哪里—结果怎样”的结构说明调试过程。

### 3.3 达成标准

- 基础达成：能独立运行代码，并判断本次是报错还是输出不一致。
- 课时达成：能根据控制台和目标输出连续修复至少 2 处问题，最终得到正确输出。
- 进阶达成：能坚持“一次修改一处、修改后立即运行”，并说明每次修改的证据。

## 4. 学习主线

本章采用“明确目标—运行代码—阅读反馈—定位问题—修改一处—再次运行”的调试闭环：

```text
明确任务目标和预期结果
        ↓
先不改代码，直接运行一次
        ↓
阅读控制台报错或实际输出
        ↓
定位需要优先检查的代码行
        ↓
每次只修改一处问题
        ↓
再次运行并与目标输出比较
```

## 5. 章节内容结构

### 5.1 教师演示：代码看起来差不多，为什么运行不了

教师投屏展示目标输出和 PPT 中的预置代码，示范先运行、再依据反馈修改：

目标输出：

```text
我的调试记录
1. 运行代码
2. 查看运行结果
3. 修改后重新运行
```

预置代码：

```python
print("我的调试记录")
print("2. 查看运行结果")
print("1. 运行代码)
print（"3. 修改后重新运行"）
```

这段演示代码包含缺少英文引号、使用中文括号和输出顺序错误，用于教师说明不同类型的反馈；其中中文括号和调换行序不作为本课学生独立代码题的必做修改。独立题只保留缺引号与缺右括号两处可定位的错误。

### 5.2 方法一：先分清“报错”和“结果不对”

| 运行反馈 | 学生判断 | 下一步 |
| --- | --- | --- |
| 控制台出现报错，目标内容没有正常输出 | 代码不能运行 | 查看提示位置，先修复语法书写问题 |
| 控制台正常输出，但文字、标点或行序与目标不同 | 代码能运行但结果不对 | 逐行比较目标输出和实际输出 |
| 控制台输出与目标逐字、逐行一致 | 本轮任务完成 | 简要记录最后一次修改 |

本章不要求学生记忆英文报错名称，只要求能从反馈中提取“优先检查哪一行”和“这一行附近哪里不完整”。

### 5.3 方法二：从控制台回到对应代码行

学生读取反馈时按固定顺序检查：

1. 控制台是否指出了某一行或显示了附近代码。
2. 该行的 `print` 是否拼写正确。
3. 是否使用一对英文小括号。
4. 文字两侧是否有成对英文引号。
5. 该行输出内容是否与目标对应行一致。

如果平台返回的提示较长，教师只要求学生圈出行号和附近代码，不逐句翻译英文报错。

### 5.4 方法三：一次只修改一处

独立练习中，学生第一次运行后先根据反馈给第 3 行补上英文双引号，然后立即再次运行；新提示出现后，再给第 4 行补上英文右括号。第三次运行时核对输出，不要求移动或复制代码行。

一次只修改一处有两个目的：

- 能确认刚才的修改是否真的解决了对应问题。
- 如果出现新现象，容易判断它与哪次修改有关。

### 5.5 方法四：重新运行才算完成一次调试

学生每次修改后都必须点击运行，用新的控制台结果验证，不能以“我觉得已经改好了”作为结束条件。

调试记录使用三列表：

| 第几次运行 | 我发现了什么 | 我修改了哪里，结果怎样 |
| --- | --- | --- |
| 第 1 次 | 第 3 行文字右侧缺少英文引号 | 补上引号；再次运行后出现新的提示 |
| 第 2 次 | 第 4 行缺少英文右括号 | 补上括号；再次运行后代码可以运行 |
| 第 3 次 | 四行输出与目标一致 | 完成任务，不再修改代码 |

本章结论：**运行结果是调试的证据；修改后再次运行，才能证明问题真的解决了。**

## 6. 课堂活动设计

### 6.1 课堂节奏

| 时间 | 环节 | 教师/平台行为 | 学生活动 | 产出 |
| --- | --- | --- | --- | --- |
| 0～5 分钟 | 先运行再判断 | 投放预置错误代码，要求学生不修改先运行 | 观察控制台，判断“报错”还是“结果不对” | 第一次运行证据 |
| 5～12 分钟 | 教师示范调试 | 示范读取提示位置、回到对应代码行、修改一处并再次运行 | 跟随完成第一轮修复 | 第一条调试记录 |
| 12～18 分钟 | 快速辨析 | 展示 4 个控制台状态和输出结果 | 判断下一步应检查语法还是比较输出 | 反馈分类结果 |
| 18～33 分钟 | 核心任务 | 发布含 2 处缺失标点的 `print()` 调试任务 | 连续运行、定位、单点修改和复测 | 正确输出、调试记录 |
| 33～36 分钟 | 个人复盘 | 出示“运行次数—发现—修改—新结果”的记录格式 | 每人核对自己的运行结果和修改证据 | 个人调试记录 |
| 36～44 分钟 | 选择题小测 | 发布 5 道个人单选题 | 独立判断报错原因、输出差异和下一步操作 | 个人小测成绩 |
| 44～45 分钟 | 收束 | 用一句话回顾调试顺序 | 学生对照自己的运行过程完成口头总结 | 课时反思 |

### 6.2 核心任务：让实际输出与目标输出一致

任务目标：

> 修复预置代码，使控制台输出与给定的四行目标输出逐字、逐行一致。

学生使用《调试我的学习步骤》的预置代码，不需要新建或保存文件。该题与第 5.1 节的教师演示题不同：

```python
print("我的调试步骤")
print("1. 先运行")
print("2. 看结果)
print("3. 改完再运行"
```

目标输出依次是“我的调试步骤”“1. 先运行”“2. 看结果”“3. 改完再运行”，每项各占一行。

任务要求：

1. 未运行前不允许直接改代码。
2. 每次运行后先记录“报错”或“结果不对”。
3. 根据控制台或目标输出，记录本轮优先检查的代码行。
4. 每次只修改一处，然后立即点击运行。
5. 最终结果必须与目标输出逐字、逐行一致。
6. 每人至少记录 2 次“发现—修改—新结果”，最终再核对一次输出。

教师不在任务开始时一次性公布两处问题，也不要求学生抄写英文报错；重点是根据平台真实反馈完成连续调试。

### 6.3 分层支持

基础层：

- 在题目侧栏固定展示目标输出。
- 提供“报错 / 结果不对 / 已一致”三个状态供勾选。
- 提供英文引号、英文括号、逐行对照三张提示卡。

达标层：

- 独立完成至少 3 次运行。
- 每轮根据反馈只修改一处。
- 最终输出与目标完全一致并完成调试记录。

挑战层：

- 修复代码后，用另一组 `print()` 顺序设计一个“能运行但结果不对”的调试题。
- 自己预测新题的输出并运行验证。
- 比较“一次改两处”和“一次改一处”哪种方式更容易确认错误来源。

## 7. 平台内容与交互规格

本章优先复用现有 AI 课程“小节 + 编程题编辑器 + 代码运行 + 选择题小测”能力。手动改代码作为每人的课堂练习；课末小测独立作答，以选择题计分。

### 7.1 课程目录

- 大单元：`第二单元：像程序员一样检查和改进方案`
- 小节：`2.1 在编辑区调试第一段代码`
- 年级：`七年级`
- 排序：大单元第 2，小节第 1。
- 知识点分类统一使用：`2.1 运行与调试`。

### 7.2 课中互动

本课的核心活动直接在学生平台完成：

- 编程题页面同时呈现目标输出、预置错误代码、编辑区、运行按钮和控制台。
- 学生可以反复修改代码并运行，不要求下载、命名或保存文件。
- 预置代码只使用学生已经接触过的 `print()`、字符串、英文括号和英文引号。
- 课中呈现“下一步应检查哪里”“修改后为什么要再次运行”等选择题。
- 课末发布 3～5 题个人选择题小测。
- 教师在题库中按小节和难度抽取题目组成小测。
- 小 P 助手只提供追问和提示，不直接给出完整任务答案。

### 7.3 小 P 引导原则

当学生询问“这段代码哪里错了”时，小 P 按以下顺序引导：

1. 先问：“你已经点击运行了吗？控制台显示了什么？”
2. 再问：“提示指向哪一行？这一行的括号和引号是否成对且为英文符号？”
3. 如果代码能运行，提示学生逐行比较目标输出和实际输出。
4. 鼓励学生只修改当前发现的一处，然后再次点击运行。
5. 不直接一次性给出完整标准答案。

推荐提示语：

- “先把控制台最后几行读给我，它提示你检查哪一行？”
- “这一行左边和右边的引号是一对吗？”
- “现在代码已经能运行了，实际输出与目标输出从第几行开始不同？”
- “你修改后重新点击运行了吗？新的结果是什么？”

## 8. 题库设计

### 8.1 题量与难度

本课题库包含 10 道单项选择题：

- 容易 7 题：根据运行反馈判断问题类型、比较目标与实际输出、决定修改后的下一步。
- 中等 2 题：结合短代码与反馈定位具体问题，不重复考查编辑区和按钮的名称。
- 困难 1 题：判断包含多处问题时的多轮调试顺序。

建议退出检测从题库抽取 3 题：容易 1、中等 1、困难 1；建议限时 5 分钟。

### 8.2 知识点覆盖

| 知识点 | 题数 | 主要认知要求 |
| --- | ---: | --- |
| 目标输出与实际输出 | 2 | 知道用什么标准判断运行结果 |
| 编辑区与控制台 | 1 | 能从运行反馈返回对应代码行 |
| 英文括号和英文引号 | 2 | 识别初学阶段常见书写问题 |
| 输出文字与行序 | 3 | 识别能运行但结果不符合要求的问题 |
| 修改后重新运行 | 2 | 理解复测作用并说明调试证据 |

### 8.3 示例题

#### 示例 1（容易）

题目：修改代码后，怎样才能确认刚才的问题真的解决了？

- A. 看一眼代码，觉得正确即可。
- B. 再次点击运行并查看控制台。
- C. 关闭编辑区。
- D. 把所有代码重新输入一遍。

答案：B。

解析：修改只是提出了一种修复办法，再次运行并检查新结果，才能验证修复是否有效。

#### 示例 2（中等）

题目：下面哪一行最可能因为使用中文符号而不能正常运行？

- A. `print("第一行")`
- B. `print("第二行")`
- C. `print（"第三行"）`
- D. `print("第四行")`

答案：C。

解析：C 使用了中文全角括号，Python 代码中的函数括号应使用英文半角符号 `()`。

#### 示例 3（困难）

题目：一段代码已经能够运行，但实际输出的第 2、3 行与目标顺序相反。最合适的做法是哪一项？

- A. 交换对应的两行 `print()`，重新运行并比较输出。
- B. 删除全部代码，从头编写另一种程序。
- C. 反复点击运行，不修改代码。
- D. 忽略顺序，因为程序没有报错。

答案：A。

解析：当前问题是输出顺序，不是代码无法运行；交换对应输出行是针对性最强的修改，修改后仍需重新运行验证。

## 9. 评价设计

### 9.1 过程性评价

本章过程性评价满分 10 分：

| 维度 | 分值 | 评分说明 |
| --- | ---: | --- |
| 主动运行 | 2 | 未先照抄答案，能用首次运行获取反馈 |
| 阅读反馈 | 2 | 能判断报错或结果不一致，并定位相关代码行 |
| 针对性修改 | 2 | 修改与当前反馈对应，没有无依据地重写全部代码 |
| 连续验证 | 2 | 每次修改后都再次运行，直至结果正确 |
| 调试表达 | 2 | 能用运行次数、发现、修改和新结果说明过程 |

不以学生是否写出与参考答案完全相同的句子为评分标准。

### 9.2 课末个人小测

从本课题池抽取 3～5 道单选题，覆盖：根据简短报错定位标点问题、比较目标与实际输出、判断修改后下一步操作。学生在平台独立作答，系统自动计分。课堂代码调试通过运行结果与个人记录观察，不强制编入小测评分。

达标判定：小测正确率至少 80%，且课堂练习能够独立完成“运行—修改—再次运行”并获得正确输出。

### 9.3 教师观察点

- 学生是否在第一次运行前就等待教师公布答案。
- 学生能否区分“报错”和“输出与目标不一致”。
- 学生能否根据控制台回到相关代码行，而不是随机修改。
- 学生修改后是否主动再次点击运行。

## 10. 教师教学用语建议

- 导入：“程序员看到结果不对，不会先把所有内容删掉，而会先找到错误从哪里开始。”
- 追问：“控制台给了你什么证据？它让你优先检查哪一行？”
- 纠错：“先给我证据，再告诉我准备修改哪一步。”
- 强化：“一次只处理当前发现的问题，修改后立即再运行。”
- 衔接：“下一课我们会发现，同一个问题可能有多套正确方案；除了能完成任务，还要学会比较哪套更适合当前情境。”

## 11. 功能与内容边界

本章内容包包含：

- 编辑区调试闭环、运行反馈检查表和调试记录表。
- 教学目标、课堂流程和多轮调试任务单。
- 分层支持、评价量规和教师引导语。
- 10 道调试方法选择题的命题规格及正式题库。

本期不包含：

- 变量、输入输出函数、条件和循环等新语法。
- 超出 `print()` 范围的独立编程任务。
- 拖拽排序、开放题在线提交、同伴互评等新平台功能。
- Python 英文报错名称的背诵、断点或专业调试器。
- 重复讲授“什么是明确指令”和“什么是算法”的概念课。

## 12. 资源约束

- 使用现有 AIUnit、Problem、AIChoiceQuestion、AIQuizSession 和代码运行能力。
- 课程内容以中文呈现，术语数量控制在七年级学生可理解范围内。
- 单题题干尽量控制在 120 字以内，四个选项表达长度接近。
- 每道题必须包含解释“为什么”的答案解析，避免只重复正确选项。
- 题目不依赖特定设备型号、家庭条件或学生个人隐私。

## 13. 非功能需求

- 可理解性：示例只使用学生刚学过的 `print()`、字符串和多行输出。
- 可访问性：成功、报错和输出不一致不能只用颜色表示，必须同时显示文字状态。
- 认知负荷：一轮只要求处理一处问题，不要求翻译或背诵完整英文报错。
- 一致性：单元命名、年级标签、难度值和 JSON 字段与现有 AI 选择题规范一致。
- 可维护性：选择题按独立 JSON 内容包保存，调试编程题沿用现有题目目录和模板代码格式，便于审核、导入和后续修订。

## 14. 验收标准

1. 课程不再把“明确、有序”和算法定义作为新知识重复讲授，而将其作为调试检查标准。
2. 一课时流程总时长不超过 45 分钟，包含教师示范、个人编辑区实操、个人复盘和选择题小测。
3. 核心内容完整覆盖“明确目标—运行代码—阅读反馈—定位问题行—修改一处—再次运行”。
4. 核心任务让学生在平台中经历至少 3 次真实运行，并最终得到正确输出。
5. 分层任务覆盖基础、达标和挑战三类学生。
6. 评价量规可观察、可记录，不以唯一措辞作为正确标准。
7. 题库包含 10 道单选题，难度分布为 7 道容易、2 道中等、1 道困难。
8. 每道正式题目包含题干、A～D 四个选项、唯一正确答案、难度、知识点分类和答案解析。
9. 正式内容不引入本章边界外的新 Python 语法，也不要求新增平台功能。
10. 学生不需要保存或上传文件，可在现有编辑区完成课堂调试活动，并独立完成选择题小测。

## 15. 成功指标

- 课堂退出检测达标率不低于 80%。
- 至少 80% 的学生能独立完成一次“运行—定位—修改—再次运行”。
- 至少 70% 的学生能在没有教师提醒时做到每次修改后主动运行。
- 教师能在现有平台中按“2.1 运行与调试”筛选本课编程题和选择题。
- 试教后收集到的主要问题能够归类到内容难度、时间安排或题目表达，并用于下一版修订。
