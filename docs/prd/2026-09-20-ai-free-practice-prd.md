# AI 课学生端“自由练习”功能 PRD

## 1. 背景与问题

当前 AI 课学生端包含“我的小测”和“题库练习”两个 Tab。学生若只想临时编写、运行一段 Python 代码，必须先进入一道题目；题目描述、提交评测、得分和历史记录等内容会干扰纯粹的代码实验。

同时，小 P 助手只能在已有题目或小测编程题页面获得代码上下文。学生在自由编程时若希望询问当前代码，仍需手动复制粘贴，操作成本较高，也容易遗漏最新修改。

## 2. 目标

在 AI 课学生端新增“自由练习”Tab，为学生提供一个最小化的 Python 实验环境：

- 只展示代码输入框、运行按钮和运行结果。
- 代码使用 `input()` 时，通过弹窗收集学生输入后再执行。
- 小 P 助手实时获得当前代码框中的最新代码，并在学生发送消息时自动随上下文提交。
- 复用现有安全隔离执行队列，不引入浏览器本地执行或新的执行服务。

## 3. 用户故事

1. 作为学生，我可以在 AI 课首页切换到“自由练习”，直接输入 Python 代码并运行。
2. 作为学生，当代码需要标准输入时，我会看到输入弹窗，可填写一行或多行输入后运行。
3. 作为学生，我可以在自由练习时直接询问小 P；小 P 能看到代码框里的最新代码，无需我复制粘贴。
4. 作为学生，我只看到代码实验需要的内容，不看到题目、题干、分数、提交评测或提交历史。

## 4. 功能范围

### 4.1 AI 课 Tab

在 AI 课学生端现有 Tab 列表中增加第三项：

- 我的小测
- 题库练习
- 自由练习

“自由练习”仅在 AI 课展示，信息科技课页面不展示。

### 4.2 自由练习编辑器

自由练习面板只包含：

- Python 代码编辑器（复用 Monaco Editor）。
- “运行代码”按钮。
- 运行结果区域。

不包含：

- 题目标题、题目描述或题干。
- 标准输入常驻输入框。
- 提交评测、得分、通过状态或测试点。
- 恢复模板、答案、提交历史或教师配置。

编辑器初始内容为空。学生在当前页面的 Tab 间切换时，已输入代码保留；刷新页面后不保证保留。

### 4.3 代码运行

- 点击“运行代码”后复用现有 `POST /api/ai/run_code/` 异步执行链路和任务轮询。
- 无代码时禁用运行按钮。
- 排队或运行期间禁用重复运行，并显示明确的“排队中”或“运行中”状态。
- 执行完成后展示标准输出；无输出时显示“（无输出）”。
- 执行失败、超时、资源受限或服务异常时，在运行结果区域展示适合学生理解的错误信息。
- 页面卸载时取消前端轮询，避免卸载后的状态更新。

### 4.4 输入弹窗

- 当代码包含 Python `input(...)` 调用时，点击运行先打开输入弹窗，不立即提交执行。
- 弹窗提供多行文本框；每一行对应一次标准输入，完整内容作为 `stdin` 传给现有执行接口。
- 点击“运行”关闭弹窗并执行；点击“取消”关闭弹窗且不执行。
- 输入内容仅用于本次运行。再次运行含 `input()` 的代码时重新弹窗输入。
- 本期沿用现有题目页的检测方式和交互，不实现运行中的真正交互式终端。

### 4.5 小 P 助手上下文

进入“自由练习”Tab 后，注册新的页面上下文：

```json
{
  "type": "ai_free_practice",
  "title": "自由练习",
  "code": "学生代码框中的最新代码"
}
```

- 学生每次修改代码时同步更新上下文，使小 P 在发送消息的瞬间读取最新代码。
- 学生无需复制或粘贴代码。
- 离开“自由练习”Tab 时清除该上下文，避免小 P 在“我的小测”或“题库练习”列表页继续携带旧代码。
- 后端为 `ai_free_practice` 构建专用系统提示，包含当前代码并要求小 P 优先结合代码解释、定位问题或给出提示。
- 延续现有教学约束：小 P 不直接给完整答案，回答应面向中学生、简短且有引导性。
- 对客户端代码字段在后端进行长度截断，避免超大上下文；建议与现有小测编程题一致，上限 20,000 字符。

## 5. UI / UX 规格

- “自由练习”Tab 与现有两个 Tab 使用相同的视觉样式、键盘焦点和 `role="tab"` / `role="tabpanel"` 可访问性结构。
- 自由练习面板保持单栏，不展示额外说明卡片。
- 编辑器使用 Python 语法高亮、深色主题、自动布局、4 空格缩进，并隐藏 minimap。
- 运行结果使用等宽字体并保留换行与空格。
- 输入弹窗复用现有 IDE 弹窗的遮罩、输入框和按钮样式，降低学习成本。
- 小 P 助手上下文徽标显示“自由练习”，不显示“题目：自由练习”或“小测：自由练习”。

## 6. 资源与技术约束

- 前端：React、Monaco Editor、现有 `ChatContext`、现有执行任务轮询工具。
- 后端：Django REST Framework、现有执行队列和本地 runner。
- 不新增数据库表，不记录自由练习代码、运行结果或成绩。
- 不修改 runner 协议，不实现 WebSocket、PTY 或运行中交互输入。
- 继续遵守现有学生代码执行权限、速率限制、代码/输入大小限制和资源隔离策略。

## 7. 功能边界

本期不包含：

- 自动保存、云端草稿、历史代码或运行历史。
- 文件树、多文件项目、第三方包安装。
- 调试器、断点、终端命令或图形化输出。
- 代码提交、教师查看、评分、排行榜或学习统计。
- 运行过程中逐次弹出多个输入框；多次 `input()` 由学生在一次弹窗中按行填写。
- 小 P 自动发送消息或主动改写编辑器代码。

## 8. 非功能需求

- 安全：所有代码仍在既有隔离 runner 中执行，前端不执行任意 Python。
- 稳定性：重复点击不会创建并发重复任务；请求失败后可再次运行。
- 可访问性：Tab、弹窗、编辑器和按钮具有明确的可访问名称，弹窗打开后输入框自动聚焦。
- 响应式：在现有学生端支持的桌面和平板宽度下可正常使用。
- 兼容性：不改变现有“我的小测”“题库练习”、题目页和小测页的行为。

## 9. 验收标准

1. AI 课学生端显示“自由练习”Tab，信息科技课不显示。
2. 切换到自由练习后，只出现代码编辑器、运行按钮和运行结果所需界面。
3. `print("hello")` 能通过现有异步执行服务运行并显示 `hello`。
4. 含 `input()` 的代码点击运行后先出现输入弹窗；提交输入后，接口收到对应 `stdin` 并显示正确输出。
5. 输入弹窗取消后不调用运行接口。
6. 排队、运行、成功、无输出、运行错误、超时及服务异常都有清晰状态。
7. 编辑器代码变化后，小 P 下一次发送请求携带最新 `ai_free_practice.code`，无需学生复制粘贴。
8. 后端小 P 提示中能读取自由练习代码，且代码长度受到限制。
9. 离开自由练习 Tab 后，小 P 不再携带自由练习代码上下文。
10. 现有学生 Dashboard、聊天助手、执行 API 及题目页相关测试保持通过。

## 10. 成功指标

- 自由练习核心交互的前端测试全部通过。
- 聊天上下文构建的后端测试全部通过。
- 现有回归测试无新增失败。
- 功能不新增数据库迁移和后端执行端点。
